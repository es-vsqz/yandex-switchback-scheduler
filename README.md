# yandex-switchback-scheduler

Автоматическое включение/выключение РК для switchback-теста nbd (RU, аккаунт `porg-y7vq4sb5`, 17.08–27.09.2026) по расписанию из [таблицы Дани](https://docs.google.com/spreadsheets/d/11w4PKM9nvQ0RkW1K58v0Tbot8eWJJLT2n17QOBhfeaw) (зафиксировано в Jira ASMARKET-1819).

Раньше расписание переключали руками 2 раза в неделю. Теперь этим занимается робот: каждые 10 минут он смотрит, какое сейчас должно быть состояние у каждой из 32 кампаний, и если реальное состояние в Директе отличается — переключает через API. Никаких ручных действий больше не нужно.

## Что где

- `schedule.csv` — расписание на весь тест (8064 строки: 32 кампании × 252 четырёхчасовых блока). Это финальная версия, согласованная с Даней. Если расписание вдруг поменяется — нужно заново выгрузить таблицу и заменить этот файл.
- `sync_schedule.py` — главный скрипт, который всё это делает.
- `direct_api.py` — обёртка для обращения к API Яндекс.Директа.
- `.github/workflows/switchback.yml` — настройка, которая запускает скрипт каждые 10 минут на серверах GitHub (не на вашем компьютере — работает даже когда он выключен).

## Как проверить, что всё работает

Зайдите в репозиторий на GitHub → вкладка **Actions**. Там должна идти лента прогонов каждые ~10 минут:

- ✅ зелёная галочка — всё синхронизировано, никаких действий не требуется.
- ❌ красный крестик — что-то пошло не так (например, протух токен). GitHub **автоматически пришлёт письмо** на почту владельца репозитория при первом же сбое — специально следить не нужно.

Кликнув на любой прогон → на шаг «Синхронизировать расписание с Директом», можно увидеть подробный лог: какое было состояние у каждой кампании, какое должно быть, что было сделано.

## Если что-то пошло не так — как срочно всё остановить

Settings → Actions → General → Actions permissions → **Disable Actions**. Это мгновенно остановит все автозапуски. Кампании при этом останутся в том состоянии, в котором были на момент остановки — их придётся включить/выключить руками, если нужно.

## Настройка (нужно сделать один раз, до первого запуска)

1. **Получить OAuth-токен** Яндекс.Директа для `porg-y7vq4sb5`:
   - Если в компании уже есть зарегистрированное приложение для Директа (client_id) — узнайте его у коллег, которые настраивали `ppc-audit-robot` или другие интеграции с Директом.
   - Если такого приложения нет — зарегистрируйте новое на https://oauth.yandex.ru/client/new с доступом «Яндекс.Директ» (Direct API), затем получите токен по ссылке вида:
     `https://oauth.yandex.ru/authorize?response_type=token&client_id=ВАШ_CLIENT_ID`
     (откроется страница входа в Яндекс — войдите под аккаунтом с доступом к `porg-y7vq4sb5`, разрешите доступ, токен появится в адресной строке после `access_token=`).
2. **Сохранить токен в секреты репозитория** (в терминале, значение никуда не попадёт в чат и не будет видно на экране):
   ```bash
   gh secret set YANDEX_DIRECT_TOKEN --repo es-vsqz/yandex-switchback-scheduler
   ```
   Вставьте токен, когда попросит, и нажмите Enter.
3. **Сохранить логин клиента**:
   ```bash
   gh secret set YANDEX_CLIENT_LOGIN --repo es-vsqz/yandex-switchback-scheduler
   ```
   Значение: `porg-y7vq4sb5`.
4. Запустить первый тестовый прогон вручную: вкладка **Actions** → **Switchback ON/OFF (nbd RU)** → **Run workflow**. Проверить лог — если для всех 32 кампаний корректно определилось состояние, дальше всё пойдёт само по расписанию каждые 10 минут.

## После теста (после 27.09.2026)

Скрипт сам перестанет что-либо трогать после конца теста (это встроено в его логику), но для порядка после 27.09 стоит зайти в Settings → Actions и отключить workflow, чтобы он не гонял пустые прогоны.
