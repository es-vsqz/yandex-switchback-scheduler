# yandex-switchback-scheduler

Автоматическое управление показами для switchback-теста nbd (RU, аккаунт `porg-y7vq4sb5`, 17.08–27.09.2026) по расписанию из [таблицы Дани](https://docs.google.com/spreadsheets/d/11w4PKM9nvQ0RkW1K58v0Tbot8eWJJLT2n17QOBhfeaw) (зафиксировано в Jira ASMARKET-1819).

Раньше расписание переключали руками 2 раза в неделю. С 17.08 этим занимается робот — сам, без ручных действий.

## Как это работает сейчас (с 17.08.2026): TimeTargeting

Кампании **не приостанавливаются и не возобновляются**. Все 32 кампании постоянно в статусе `ON`. Показами по часам управляет встроенный в Директ временной таргетинг (`TimeTargeting`): у каждой кампании задан почасовой коэффициент ставки — 0% в часы, когда по плану Дани должен быть OFF, 100% в часы ON. Директ учитывает это в реальном времени в момент показа, без отдельного шага «включить кампанию».

- `time_targeting.py` — считает нужные коэффициенты из `schedule.csv` на скользящее окно в 7 дней вперёд.
- `push_time_targeting.py` — заливает это в Директ. Работает несколько раз в сутки (`.github/workflows/time_targeting.yml`, cron каждые 6 часов) — заливка идемпотентна, повторный запуск ничего не портит, лишняя частота только снижает риск, что пропуск одного прогона оставит устаревший план дольше, чем на несколько часов.

### Почему не suspend/resume (как было раньше)

Первую неделю теста расписание переключалось через `sync_schedule.py` — прямые вызовы `campaigns.suspend`/`campaigns.resume` каждые несколько минут. Отказались от этого по двум причинам, которые не лечатся тюнингом:

1. **Лаг активации.** Возобновление кампании после паузы — не мгновенный флаг, кампании требуется время на переактивацию. Это поведение самого Директа, не наше.
2. **Слом обучения автостратегий.** Частые паузы/возобновления сбрасывают или портят статистику, по которой автостратегия подбирает ставки — это било не только по таймингу, но и по эффективности закупки.

`TimeTargeting` устраняет обе проблемы архитектурно: кампания никогда не останавливается, значит нет ни лага реактивации, ни сброса обучения.

Код старого механизма (`sync_schedule.py`, `direct_api.suspend`/`resume`) оставлен в репозитории как аварийный откат — workflow `switchback.yml` больше не запускается по расписанию, только вручную (`workflow_dispatch`), на случай если `TimeTargeting` придётся временно отключить.

## Что где

- `schedule.csv` — расписание на весь тест (8064 строки: 32 кампании × 252 четырёхчасовых блока). Финальная версия, согласованная с Даней. Если расписание поменяется — нужно заново выгрузить таблицу и заменить этот файл (и заново прогнать `time_targeting.yml`, чтобы залить обновлённый план).
- `time_targeting.py`, `push_time_targeting.py` — текущий механизм (см. выше).
- `direct_api.py` — обёртка для обращения к API Яндекс.Директа (и старый suspend/resume, и текущий TimeTargeting).
- `sync_schedule.py`, `.github/workflows/switchback.yml` — старый механизм, оставлен для аварийного отката.
- `resume_all.py`, `.github/workflows/resume_all.yml` — разовый скрипт перехода (перевёл все 32 кампании в постоянный ON 17.08.2026), обычно больше не нужен.
- `test_connection.py`, `.github/workflows/test-connection.yml` — проверка связи с Директом (только чтение, ничего не меняет).

## Как проверить, что всё работает

Вкладка **Actions** на GitHub → workflow **Push TimeTargeting (nbd RU)**. Прогоны идут раз в 6 часов:

- ✅ зелёная галочка — план залит, всё в порядке.
- ❌ красный крестик — что-то пошло не так (например, протух токен). GitHub автоматически пришлёт письмо на почту владельца репозитория при первом же сбое.

Кликнув на прогон → шаг «Залить TimeTargeting в Директ», можно увидеть, какие 7 строк (по одной на день недели) были отправлены для каждой кампании.

Проверить в самом Директе: зайти в любую из 32 кампаний → «Временной таргетинг» — там должно быть видно расписание по часам, совпадающее с планом.

## Если что-то пошло не так — как срочно всё остановить

Settings → Actions → General → Actions permissions → **Disable Actions**. Остановит все автозапуски. Кампании при этом останутся в статусе ON с последним залитым расписанием показов — если нужно немедленно прекратить показы вручную, это делается через обычную паузу кампании в интерфейсе Директа.

## После теста (после 27.09.2026)

По мере того как скользящее окно [сегодня; +6 дней] проходит дальше 27.09, `push_time_targeting.py` перестаёт находить план для всё большего числа дней недели — Директ в ответ сам проставляет для них дефолт (100% = обычный показ, без ограничений). Так что к моменту, когда сам тест закончится, кампании уже плавно вернутся к обычному режиму показов без какого-либо ручного вмешательства. После 27.09 стоит зайти в Settings → Actions и отключить `time_targeting.yml`, чтобы не гонять лишние прогоны.
